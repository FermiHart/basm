# BearBasm Supported Subset v1

Status: normative

This contract describes Basm's bounded source language and the distinction
between the public assembler and the separate compatibility binary. The public
assembler encodes in 64-bit mode only. Compatibility-only modes do not become
available by selecting a different output format; see the profile table below.

Modeled forms and their declared metadata are in `isa/INVENTORY.md`.
`--list-instructions` lists registered vocabulary, while `--list-forms` lists
the 109 modeled forms (33 fixed, 34 GPR RR, 2 bounded rotates, 40 bounded SSE).
The public vocabulary has 203 mnemonics; the selector-free dispatcher has 207, including the four historical
entries `pusha`, `pushad`, `popa`, and `popad` excluded from modern profiles.
These inventories are intentionally not interchangeable.

This document defines the source-language boundary of BearBasm. It complements
`POLITICA-BASM.md`, which defines compatibility and extension policy. BearBasm
is not a complete NASM implementation. Acceptance outside this contract is a
bug unless promoted through the policy and its gates.

## 1. Conformance

A parity-class source has three normative observables against NASM:

1. byte-identical `.text`;
2. identical normalized symbols;
3. identical normalized relocations.

ELF layout, padding, and string-table offsets are not normative when those
observables agree. Flat `bin` output is compared byte for byte. BearBasm-only
syntax must be listed in `tests/encoding_subset_allowlist.txt`; all other
unsupported syntax must fail instead of being silently reinterpreted.

The implementation and this document have equal change authority: a change to
the instruction inventory must update both in one patch. `tests/subset_spec_test.sh`
enforces that rule mechanically.

## 2. Outputs And Modes

- `-f elf64`: x86-64 ELF relocatable object (`ET_REL`) with symbols and RELA
  relocations.
- `-f bin`: flat concatenation of emitted content sections; unresolved
  relocations are rejected.
- `BITS 64`: the encoding mode for the public assembler and explicit profiles.
  `BITS 16` and `BITS 32` are available only through the compatibility interface
  or the registered Beyond bootstrap exception described below. Encoding modes
  do not select 16-bit or 32-bit object formats.
- `org EXPR`: origin for flat binaries.
- `default rel` and `default abs`: default symbolic memory-address policy.

Mach-O, COFF, PE, a.out, 16-bit objects, and 32-bit objects are outside v1.

### Target profiles

| Invocation | Encoding modes | Bootstrap access |
|---|---|---|
| Public `basm`, with or without `--target-profile public` | 64 only | Unavailable |
| `basm-compat --target-profile public` | 64 only | Unavailable |
| `basm-compat --target-profile beyond` | 64 by default | Exact registered AP source only |
| `basm-compat` without a target selector | Compatibility BITS 16/32/64 | Compatibility behavior, outside the public profile |

Explicit profiles reject malformed BITS directives and the legacy stack/far-jump
forms excluded by their policy. Normal 8-, 16- and 32-bit operands remain
available where their encoders support them in long mode.

`--bootstrap ap-trampoline-v1` requires the `beyond` profile and the exact bytes
of the registered AP trampoline, with no command-line defines or include paths.
Its registered source may transition through 16/32/64-bit modes. Filename alone
grants no exception. The public build cannot enable this path.

`--profile` selects timing telemetry; it is unrelated to `--target-profile`.
Profiles constrain assembly behavior, not the runtime safety of emitted bytes.

## 3. Lexical And Symbol Syntax

Assembler names are bounded to 255 bytes, including any qualified scope.
Accepted names retain all bytes in host and sovereign builds; distinct final
bytes must not collapse. Names generated by structures must also fit this
boundary. Memory-operand text is bounded to 255 bytes including brackets;
overlong names/operands fail rather than being truncated.

- One label, directive, data definition, or instruction per logical line.
- `;` starts a line comment outside a quoted value.
- Global labels, dot-local labels, and anonymous `@@`, `@F`, `@B` labels.
  Qualified dotted names remain complete expression terms, e.g.
  `entry.end-entry.begin`; their suffixes are not discarded.
- Duplicate definition at the same section offset is idempotent; a different
  section or offset is an error.
- Decimal and `0x` hexadecimal integers; single-quoted characters and
  backtick escaped characters.
- Integer expressions with parentheses, unary `-`, `*`, `+`, `-`, `<<`, `>>`,
  `&`, `^`, and `|`; `$` is the current offset and `$$` is section start.
- Symbol expressions contain at most the relocation forms representable by
  v1. Ambiguous multi-symbol relocation expressions are rejected or resolved
  only when all symbols are local and known.

## 4. Directives

The v1 directive set is:

- Symbols: `global NAME`, `global NAME:function [SIZE_EXPR]`, `extern`, `weak`,
  `NAME equ EXPR`. An explicit function extent, e.g.
  `global NAME:function (end_label-NAME)`, emits ELF `STT_FUNC` and `st_size`.
  The size grammar is decimal/`0x` integers, labels, unary/binary `+`/`-`, and
  parentheses (255 bytes, at most 16 nested parentheses). Dot-local labels use
  the declaration's label scope. All labels, including forward references,
  must be defined in the function's own executable PROGBITS section, and their
  signed coefficients must sum to zero (an absolute size, not an address).
  Literals and intermediate results are bounded to `[-LONG_MAX, LONG_MAX]`;
  the final size must be nonnegative and fit from `NAME` to the section end.
  EQU aliases, `$`/`$$`, other operators, extra operands and unresolved,
  external or cross-section labels are rejected, even if they cancel out.
  Validation runs after the final layout pass, before publication in either
  output format. Bare `global NAME` and size-unspecified `NAME:function`
  retain size zero. No size is inferred from alignment, tables or other labels.
  The NASM parity and refusal contract is exercised by `tests/newfunctionsizegate.sh`.
- Local functions: `static NAME:function SIZE_EXPR` uses the same explicit
  extent grammar and validation as `global`, but emits `STB_LOCAL STT_FUNC`.
  The size is required; mixing static with global, weak or extern is rejected.
  This is NASM ELF syntax, not a BASM-only alias.
- Local untyped extents: `static NAME:notype SIZE_EXPR` emits `STB_LOCAL`
  `STT_NOTYPE` with a required explicit bounded size. The same size grammar and
  section-end bound apply, including zero; code, data and NOBITS sections are
  permitted. No type is inferred from a nonzero size; unannotated labels retain
  size zero. Binding/type conflicts, cross-section sizes, EQU size aliases and
  missing explicit sizes are rejected. This is NASM ELF syntax, checked
  by `tests/notype_extent_test.py`, not a FUNC workaround or inferred extent.
- Sections: `section`/`segment` with `.text`, `.rodata`, `.data`, `.bss`,
  `.note.GNU-stack`, or a custom name. Custom attributes are `alloc`,
  `noalloc`, `exec`, `noexec`, `write`, `nowrite`, `progbits`, `nobits`, `note`, and
  `align=N` (literal decimal/hex power of two, 1..1073741824). Unknown attributes,
  GROUP/COMDAT, duplicates, conflicting type/permission/alignment declarations,
  and W+X are refused. Reselect by name alone or repeat the same full declaration.
  `section .note.Linux alloc noexec nowrite note align=4` emits genuine SHT_NOTE
  (type 7, SHF_ALLOC, sh_addralign 4); NOTE cannot be writable/executable or used
  on a canonical fixed section. A `.note.*` name alone still means PROGBITS.
  `alignb` retains zero padding; `align` retains its existing 0x90 padding.
  Explicit canonical section alignment is honored too: fresh `.text align=4`
  replaces the implicit default 16, while later declarations never lower a
  requirement established by an earlier explicit declaration or `align`/`alignb`.
  Bare section reselection preserves alignment. A bare `align 4` alone still
  leaves the implicit `.text` default 16, preserving existing alignment users.
  Canonical section type and permissions are fixed: `.text` is executable,
  allocated PROGBITS; `.data` is writable, allocated PROGBITS; `.rodata` is
  allocated PROGBITS; `.bss` is writable, allocated NOBITS; `.note.GNU-stack`
  is unallocated, nonexecutable, nonwritable PROGBITS. Explicit attributes may
  repeat those properties. Conflicting attributes are rejected instead of
  silently emitting a different type or permission. Use a custom section when
  different supported attributes are required; W+X remains refused.
- Explicit symbol metadata: `global NAME:data SIZE_EXPR` emits GLOBAL
  OBJECT with the same required, full-width, section-bounded extent grammar as
  local NOTYPE. `global NAME:hidden` emits defined GLOBAL HIDDEN NOTYPE with
  size zero. No type is inferred from section flags or extent. Hidden is not a
  general qualifier list: sizes, `:function:hidden`, `:data:hidden`, static,
  weak, undefined labels and conflicting redeclarations are refused.
  Purgatory's linkage macros also require `static NAME:data SIZE_EXPR` (LOCAL
  OBJECT) and `global NAME:notype SIZE_EXPR` (GLOBAL NOTYPE). Both use the same
  mandatory extent validator, including full-width integer overflow checks.
- Data: `db`, `dw`, `dd`, `dq`; reserves `resb`, `resw`, `resd`, `resq`;
  `times EXPR` over a data or reserve directive.
  Each quoted string operand emits its bytes in order and is zero-padded to a
  multiple of the directive width (1, 2, 4 or 8 bytes), matching NASM's data
  strings. Characters are not individually widened. Empty strings emit no
  bytes. Single and double quotes preserve literal bytes, including UTF-8;
  use explicit byte data when another text encoding is required.
  Backtick strings and single-byte backtick character expressions share these
  escapes: `\a`, `\b`, `\e`, `\f`, `\n`, `\r`, `\t`, `\v`, `\\`, `\'`, `\"`,
  escaped backtick, `\?`, `\xH`/`\xHH`, and one to three octal digits.
  Octal values must fit in one byte; extra digits beyond the escape's maximum
  length remain literal string bytes. Unicode escapes (`\u`, `\U`), unknown
  escapes, a hexadecimal escape without digits, and octal overflow are
  explicitly rejected. This bounded escape grammar is a NASM subset.
  Admitted custom section names retain their complete spelling in generated
  `.rela` names, including names up to the 255-byte section-name limit.
  ELF64 `dq NAME wrt ..sym` opts into `R_X86_64_64` against the named symbol
  with addend zero, instead of ordinary `dq NAME` section folding. It accepts
  one bare defined global or declared extern, including forward declarations
  and qualified dot-local names with GLOBAL binding. Targets are validated
  after the final pass. Local-binding or undefined non-extern targets, other
  modifiers/widths, expressions, comma lists and extra operands are rejected.
  `tests/newfunctionsizegate.sh` checks this NASM-parity form and unchanged default folding.
  ELF64 `dd NAME[+/-integer] - $` is one field-relative address per directive.
  The optional adjustment is one decimal/`0x` integer of magnitude at most
  2147483647; commas, extra operands, parentheses around `$`, and further
  arithmetic are rejected. A defined cross-section label emits `R_X86_64_PC32`
  against its section with label offset plus adjustment as addend; an extern
  uses the named symbol with the adjustment as addend (zero when omitted).
  Same-section labels resolve to label offset plus adjustment minus the field
  offset, bounded to signed 32 bits. Forward and dot-local labels are supported.
  Other widths, `$$`, EQU targets, unresolved non-extern labels and flat output
  are rejected. `tests/newcopypagegate.py` checks the unadjusted form and sized
  static functions; `tests/uaccess_isa_test.py` checks adjusted fields.
- Layout: `align`, `alignb`, `org`, `bits`, `default rel`, `default abs`.
- Files: `incbin FILE[, SKIP[, COUNT]]` and include lookup through source
  directory, current directory, and `-I` paths.
- Structures: `struc`, `endstruc`, `istruc`, `at`, `iend` with reserve fields.

Section, text, data, relocation, symbol, include, macro, repetition, and line
limits are implementation caps, not permission to consume unbounded memory or
CPU. Inputs beyond a cap fail before publication.

## 5. Preprocessor

The v1 preprocessor supports:

- object-like and function-like `%define` (up to four parameters), `%undef`;
- numeric `%assign`;
- `%macro`/`%endmacro`, fixed and supported variadic argument forms, `%1...`;
- `%if`, `%ifdef`, `%ifndef`, `%elif`, `%else`, `%endif`;
- `%include` with recursive cycle/depth rejection;
- `%rep`/`%endrep` with a hard expansion-count ceiling;
- structure constant generation and anonymous-local-label expansion;
- bracketed `[BITS 16]`, `[BITS 32]`, `[BITS 64]`.
- `%error MESSAGE`: an active directive fails with its expanded message before
  object/proof publication. Direct directives are handled in the preprocessor;
  deferred macro/rep directives obey the assembly-time conditional state.
  Inactive branches and unused/zero-repeat bodies do not trigger the error.
  Message text is bounded by the existing source-line limit, not executed.

Numeric `%if`/`%elif` conditions evaluate the complete integer expression after
bounded `%define` substitution, including nested numeric defines and conditions
in expanded macros. An expression is true when nonzero; one top-level
comparison (`==`, `!=`, `<`, `<=`, `>`, `>=`) can compare two integer expressions.
`<<`/`>>` remain shift operators, not comparisons. Parentheses group arithmetic
operands, not comparisons; chained comparisons and logical `&&`/`||` are outside
this subset. Undefined bare configuration names remain false, while unresolved
names in compound numeric expressions are rejected. Condition substitution uses
512-byte buffers and at most 32 convergence checks; overlong or nonconverging
expansions fail. `tests/uaccess_isa_test.py` covers the numeric uaccess conditions.

Token pasting, the complete NASM macro language, floating-point preprocessing,
and undocumented context-stack facilities are outside v1.

## 6. Operands And Addressing

- General registers: 8-, 16-, 32-, and 64-bit legacy and `r8`-`r15` forms.
  High-byte registers are rejected when a REX prefix is required.
- Segment registers: `es`, `cs`, `ss`, `ds`, `fs`, `gs` in supported `mov`
  forms and as memory overrides.
- Control registers: `cr0`, `cr2`, `cr3`, `cr4` in supported `mov` forms.
- Vector registers: `xmm0`-`xmm15` and `ymm0`-`ymm15` only for listed vector
  mnemonics.
- Memory: `[base + index*scale +/- displacement]`, with scale 1/2/4/8,
  same-width 32- or 64-bit address registers, pure displacement, `[rel SYM]`,
  `[abs EXPR]`, and segment overrides.
- Sizes: `byte`, `word`, `dword`, `qword` where an encoder requires an explicit
  memory or source width.
- Branches: inferred width plus explicit `short` and `near` where supported;
  the layout engine converges until all branch targets are stable.

Mnemonic membership does not imply every NASM operand cross-product. The
accepted forms are the fail-closed forms implemented by that mnemonic's
encoder and exercised by the differential/regression corpus. Unsupported
widths, register classes, or operand counts are errors.

`endbr64` is the literal no-operand CET landing instruction (`F3 0F 1E FA`) in
BITS 64, with no comma, extra operands or external prefixes. It remains
explicitly unmodeled in the intent schema/CFG; accepting its bytes is not a
semantic proof or authorization to execute kernel code.

Control-register MOV supports only CR0/CR2/CR3/CR4. In BITS 64, its other operand
must be r64; in compatibility BITS 16/32, it must be a low r32. Exactly two bare
operands and one correctly placed comma are required. LOCK/REP/o64 prefixes,
CR8, memory/vector operands, wrong widths and ignored extras are refused.

The following legacy SSE encodings are supported in BITS 64, using XMM0..15:

- `movaps`, `movups`, `movdqa`, `movdqu`: `xmm,xmm`, `xmm,[memory]`, `[memory],xmm`.
- `movq`: `xmm,r64`, `r64,xmm`, `xmm,[memory]`, `[memory],xmm`. Memory transfers
  are 64 bits; XMM destinations clear their upper 64 bits. XMM-XMM and MMX are
  outside this subset. Other vector moves transfer 128 bits.
- `paddd`, `paddq`, `pxor`, `por`, `pmuludq`, `punpcklqdq`, `punpckhqdq`:
  `xmm,xmm` only, with destructive destination reads and no RFLAGS writes.
- `pslld`, `psrld`: `xmm,imm8`; `pshufd`: `xmm,xmm,imm8`. Immediate is one
  decimal/hex literal in 0..255, not an expression, register, or memory operand.
  Packed shifts by 32..255 zero lanes, not a GPR-style modulo count.

SSE memory widths are inferred, not given by size keywords. Same-width 32/64-bit
base/index registers, scales 1/2/4/8, segment prefixes, signed disp32 literals,
and `[rel NAME +/- literal]` are supported; no subtracted registers, RSP index,
symbolic base displacements, arithmetic/scaled displacement expressions,
extra operands or external instruction prefixes. `default rel` works for
symbolic memory references. RIP references use the existing PC32 relocation
path. Aligned moves still require caller-provided alignment; this is not a
memory-safety proof. Existing VEX forms are unchanged, not used as replacements.

`prefetcht0 [memory]` accepts one unsized memory operand in BITS 64, using
the ordinary address/REX/segment encoder (`0F 18 /1`). Register/immediate
operands, size qualifiers, commas and symbolic base displacements are rejected
(use `[rel NAME]` for a symbolic address). Its addressing parity
and invalid forms are covered by `tests/newcopypagegate.py`.

`sbb` accepts same-width GPR register pairs (8/16/32/64) in BITS 64; it reads CF
as well as both operands. Memory/immediate forms are not included in this cut.
`movnti [memory], r32/r64` accepts optional matching dword/qword size in BITS 64.
Symbolic addresses require `rel`; malformed addresses, invalid indices and
out-of-range displacements fail. In BITS 64, explicit loads
`mov r32, dword [memory]` and `mov r64, qword [memory]` require matching
destination/source widths; they do not imply a general MOV operand cross-product.
`sfence` is the no-operand SSE store fence (`0F AE F8`), not interchangeable with
the SSE2 LFENCE/MFENCE forms.
Defined cross-section near/auto JMP/Jcc in ELF64 BITS 64 emit `R_X86_64_PC32`
against the target section at the displacement field, with target offset minus
four as addend. Extern near/auto targets use a named PC32 relocation with addend
-4; short external/cross-section and flat-output relocations fail rather than
guess a layout. These bounded forms are checked by `tests/uaccess_isa_test.py`.
Only SBB RR and SFENCE among these forms are modeled by the declarative schema;
MOVNTI, explicit memory loads and branch relocations remain outside that model.

The modeled ADC/rotate forms are `adc r32,r32`, `adc r64,r64`, `ror r64,1`, and `rol r32,8`,
unprefixed in BITS 64. ADC reads both operands and CF and writes the destination
plus AF/CF/OF/PF/SF/ZF. Rotates read/write the destination and update CF;
ROR by one defines OF, while ROL by eight leaves OF undefined. Both preserve
AF/PF/SF/ZF; 32-bit destination writes zero-extend. All four are modeled.
The rotate counts are the literal decimal tokens `1` and `8` after preprocessing,
not expressions, EQU aliases, other immediate spellings or masked-count aliases.
Other widths/counts, CL counts, memory operands, prefixes, size qualifiers,
missing/extra operands and malformed commas are refused before publication.
This is not a general ADC/rotate family. `tests/csum_copy_isa_test.py` checks
every register cross-product against NASM, output-preserving refusals, trace/CFG
metadata, and reviewed safe arithmetic-only host probes against a flag oracle.
It never executes kernel fixtures or asserts undefined OF for ROL by eight.

## 8. Relocations

ELF64 v1 emits the relocation classes needed by the in-tree consumers:
PC-relative 32-bit, absolute 64-bit, unsigned absolute 32-bit, and signed
absolute 32-bit, against named symbols or section symbols as applicable.
Flat binaries must resolve every reference during assembly.

## 9. Executable Checks

`make check` runs the standalone suite described in [docs/TESTING.md](docs/TESTING.md).
It checks the public and compatibility binaries separately and retains commands,
output and binary identities. The presence of a test is not a claim that every
integration configuration has been run for a particular build.

Additional focused checks are available in the source tree:

| Files | Scope |
|---|---|
| `tests/subset_spec_test.sh`, `isa/generate.pl --check` | Instruction-inventory synchronization and generated-form freshness |
| `tests/critical_regression_test.sh` | Operand-width and instruction regressions |
| `tests/newfunctionsizegate.sh`, `tests/newcopypagegate.py` | Explicit FUNC extents, symbol identity, field-relative addresses and PREFETCHT0 |
| `tests/uaccess_isa_test.py`, `tests/notype_extent_test.py` | Numeric conditions, dotted expressions, PC32 adjustments and LOCAL NOTYPE extents |
| `tests/csum_copy_isa_test.py` | Bounded ADC/rotate encodings, refusals, metadata and arithmetic-only host probes |
| `tests/intent_encoding_test.sh`, `tests/intent_trace_test.sh`, `tests/intent_cfg_test.sh` | Modeled forms, emitted bytes and partial trace/CFG evidence |
| `tests/layout_stability_test.sh`, `tests/layout_torture.sh` | Branch layout and target stability |
| `tests/preprocessor_limits_test.sh` | Macro, include and repetition boundaries |
| `tests/standalone/test_differential.py` | Seeded NASM comparisons with retained failures |

Use each script's explicit binary/output options and required host tools. Tests
that expect the embedded Beyond layout remain integration checks. Full compiler
reproducibility and sanitizer results require separately identified builds;
they are not implied by passing an instruction or source-inventory check.

Any syntax addition requires a reproducer, parity/extension classification,
positive and refusal tests, and an update to this document when its boundary
changes. The compatibility policy is [POLITICA-BASM.md](POLITICA-BASM.md).
