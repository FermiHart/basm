# IC03 Declarative Forms

`forms.tsv` is the checked-in source for `intent_forms.h` and `INVENTORY.md`.
This slice contains 108 forms: 33 no-explicit-operand forms, 34 GPR RR forms,
two bounded rotates, and 39 bounded SSE forms. MOV/ADD/OR/AND/SUB/SBB/XOR/CMP cover 8/16/32/64 bits;
ADC covers only 32/64, ROR only r64,1, and ROL only r32,8 (INV-730). All rows require mode 64;
there are no historical profiles, string instructions, implicit loops, general
immediate expressions or unchecked arithmetic memory forms in this slice.
INV-740 adds explicit SSE moves, packed register arithmetic, and literal imm8
shifts/shuffles. See [TINA26-SUBSET.md](TINA26-SUBSET.md) for the original-source
inventory, exact encodings, and evidence boundaries.
RET and LEAVE do have implicit stack reads, declared as `memory.stack`.
INV-703 adds SBB RR (including its CF read) and the fixed SSE store fence SFENCE.
The companion MOVNTI memory forms, explicit MOV memory loads and cross-section
JMP/Jcc relocations are supported outside this declarative slice, not modeled
by it. The public vocabulary has 202 mnemonics (206 selector-free dispatcher
entries minus four historical exclusions); mnemonic counts are not form counts.

## Regeneration

Only core Perl modules are needed. Run from the BearBasm directory:

```sh
perl isa/generate.pl --output isa/intent_forms.h
perl isa/generate.pl --format inventory --output isa/INVENTORY.md
perl isa/generate.pl --check
bash tests/isa_schema_test.sh
```

Without `--output`, the selected artifact goes to stdout; no file is written.
`--schema FILE` selects alternate input. `--check` always compares both artifacts
beside the generator and never writes, even on malformed input, drift or missing
files; it rejects `--output` and `--format`. No timestamps, host paths, locale
sorting or hash iteration order enter generated bytes. The source SHA-256 ties
both artifacts to every byte of the TSV. NASM and a host C compiler are test-only
dependencies; the generator does not invoke either or build BearBasm.

## Schema Contract

The exact header names and column order are mandatory. ASCII only, LF-terminated,
TAB-separated, no comments, blank rows, empty fields, escapes, quotes or embedded
pipes. Limits: 1 MiB input, 1024 forms, 1024 bytes/line, 192 bytes/field and 64
bytes/ID. Invalid input fails before output is opened, with a bounded diagnostic
that does not echo input data. Rows sort by mnemonic, numeric width, then encoding. IDs
are unique lowercase `[a-z][a-z0-9_]*`, independent of row indices, and must stay
stable once consumed. Duplicate mnemonic/width/encoding forms are refused.

- `id`: fixed IDs are mnemonic names; RR IDs are `mnemonic_rrWIDTH`.
  The two rotate IDs are `rol_r32_8` and `ror_r64_1`.
- `mnemonic`: closed vocabulary for this slice. Adding a family requires review
  of the validator and independent oracle tests, not just an arbitrary string.
- `operands`: `none` or `gpr,gpr`, in destination/source order, both same width.
  Bounded rotates use `gpr,8` or `gpr,1`; the count is a literal decimal token
  after preprocessing, not an expression or a general immediate placeholder.
  SSE shapes are the exact `xmm,xmm`, `xmm,mem`, `mem,xmm`, `xmm,gpr`, `gpr,xmm`,
  `xmm,imm8` or `xmm,xmm,imm8` tuples enumerated by the closed validator.
- `reads`, `writes`: sorted, unique, comma-separated symbolic state tokens;
  `none` means no declared state in that field. `dst`/`src` bind to operands.
  Architectural names such as `eax` denote that register access, including the
  architectural zero-extension of a 32-bit write. Register aliases and partial
  writes are not expanded into a formal bit-level model here.
  `memory` is the explicitly accessed memory range; `dst.address`/`src.address`
  read the effective-address registers of that operand, not the stored value.
  MOVQ memory/GPR transfers are 64 bits; an XMM destination is fully written,
  with its upper 64 bits zeroed. Other SSE destination writes are 128 bits.
- `flags`: sorted `name:action` summaries for the flag intersection of `writes`.
  Actions are `write`, `zero`, `one`, `undefined`, `unknown`. Logical ALU forms
  leave AF undefined, clear CF/OF and update PF/SF/ZF. CMP writes flags, not `dst`.
  SBB and ADC read `cf,dst,src` and write `dst` plus the arithmetic flags.
  ROR/ROL read `dst`, write `cf,dst,of`, and preserve AF/PF/SF/ZF. ROR by one
  declares `cf:write,of:write`; ROL by eight declares `cf:write,of:undefined`.
  `rflags:unknown` is opaque aggregate state and cannot mix with individual flags.
  Flag reads, if present, are in `reads`; absent flag writes are not clobbers.
- `features`: sorted requirements from `base,cpuid,msr,rdtscp,smap,sse,sse2,syscall,tsc,
  x87,xsave`; `base` stands alone. These are CPU-family/feature labels, not a
  complete CPUID predicate, CPL check or OS enablement model. XGETBV/XSETBV still
  require OSXSAVE and appropriate indices/privilege; encoding does not authorize
  execution. All rows additionally require 64-bit mode.
  SFENCE requires `sse`; LFENCE/MFENCE require `sse2`.
- `control`: `next` (ordinary continuation), `return` (RET), `system` (SYSCALL /
  SYSRETQ), `halt`, `trap`, or `barrier` (CPUID / RDTSCP / LFENCE / MFENCE / SFENCE).
  Barriers differ architecturally; this tag is not an ordering equivalence claim.
- `opcode`: 1..4 lowercase hex bytes separated by one space. For `fixed`, these
  are the complete bytes, including prefixes. For `gpr_rr`, one store-direction
  opcode only: destination in ModRM r/m, source in ModRM reg, mod=3. Encoder owns
  66/REX and must reject high-byte registers with any REX prefix. No memory form
  is implied by using a store-direction opcode.
  For `gpr_rotate`, only `ror:64:gpr,1:d1` and `rol:32:gpr,8:c1` are legal.
  The encoder owns REX, ModRM mod=3 (/1 for ROR, /0 for ROL) and ROL's byte 08;
  ROR's count one is implicit in D1. No other widths/counts/prefixes are implied.
- `width`: bits (8/16/32/64) for RR; 0 for fixed means no explicit width operand,
  not zero-bit implicit effects. SSE width is 128, except MOVQ's 64-bit transfer.
  `encoding`: `fixed`, `gpr_rr`, `gpr_rotate`, or one of the seven `sse_*` kinds.
  Rotate width is 32 or 64 as constrained above. `mode`: `64`.

## Integration API

The generated header has no includes or foundation dependencies. It defines
`typedef struct IntentForm` with string fields `id, mnemonic, operands, reads,
writes, flags, features, control`, then `unsigned char opcode[4]`, and integer
fields `opcode_len, width, encoding`, in that order. It exports
`INTENT_FIXED=0`, `INTENT_GPR_RR=1`, `INTENT_GPR_ROTATE=2`, `static const IntentForm g_intent_forms[]`
and `#define INTENT_FORM_COUNT 108`, plus `INTENT_SSE_RR/RM/MR/XG/GX/SHIFT/SHUF`
values 3..9. `INTENT_SSE_NAMES(kind)` expands the unique closed SSE registration
vocabulary, keeping registration in the existing single constructor loop.
Unused opcode slots are zero-filled. SSE opcode bytes include a mandatory
66/F3 prefix where needed; the encoder inserts REX after that prefix, adds
ModRM/SIB/displacement and literal imm8, and selects REX.W only for MOVQ GPR
transfers. PSLLD/PSRLD select 0F 72 /6 and /2 respectively.
The product's typed fixed/RR/rotate/SSE encoder and explanation trace consume these rows;
other accepted forms remain explicitly unmodeled.

## Evidence Boundary

Bytes originate in `modules/02_encoding.inc`'s fixed emitters and existing
`enc_mov_rr` / `enc_alu_rr` store-direction paths, cross-checked independently
against NASM `BITS 64` (2.16.01 for the initial local run). The architectural
reference is Intel SDM Volume 2's instruction definitions.
CWDE is `98`, CDQE is `48 98`, CDQ is `99`, CQO is `48 99`, and SYSRETQ is
`48 0f 07`. The pre-integration direct SYSRETQ switch arm had only `0f 07`;
the existing `o64 sysret` path had the correct full encoding. The schema uses
the architectural/NASM bytes rather than perpetuating that switch-arm error.

`system.unknown` is an opaque read/write effect for unmodeled system state,
serialization, interrupt shadows, privilege transitions, MSRs and similar
behavior. It must never be interpreted as harmless or removable. `x87.state`
is likewise coarse. Faults, environment-dependent effects, CET, alias-aware
liveness, memory safety and semantic equivalence are not proven by these rows.
Even `none` is not permission to elide, reorder or execute an instruction.

INV-594's local check verifies strict parsing, freshness, deterministic generation,
C API round-trip, NASM bytes for all fixed forms and RR width/register samples,
and actual set intersections of declared flag metadata. It never executes the
assembled bytes, including unprivileged ones. These are encoding and metadata
checks, not semantic proofs. `test-intent-encoding` checks the selected product's
bytes; `test-intent-trace` checks explanation and partial CFG structure. INV-703's
`test-uaccess-isa` and `test-notype-extent` are separate NASM parity/refusal gates
for the bounded uaccess additions. None substitutes for product/global gates.

INV-730's `tests/csum_copy_isa_test.py` independently checks all 512 ADC register
pairs and 32 rotate register/count cases under default/public/beyond, illegal
operands with preserved output, and declared CF/read/write/OF metadata plus
fallthrough CFG edges. Its only executable generated code is a reviewed safe
SysV leaf wrapper: register moves, CMP, CLC/STC, ADC/ROR/ROL, PUSHFQ/POP, writes
to caller-owned storage and RET. The complete wrapper must match NASM before
RX mapping. Integer reference arithmetic checks carry-in 0/1, zero/one/63,
sign/overflow/carry/parity/auxiliary-carry edges and deterministic random values;
counts zero/63 are rejected, not executed. Undefined ROL-by-eight OF is never
asserted. This bounded host oracle does not turn the schema/CFG into a general
semantic, taint, memory-safety or kernel-execution proof.
